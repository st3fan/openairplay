# `--tui`: full-screen now-playing display with terminal artwork

Goal: give the receiver binary a `--tui` mode that takes over the terminal
and shows **what is currently playing** — track title, artist and album
centered on screen — plus the **cover art rendered as a real image** on
terminals that can do it (Ghostty, Kitty, WezTerm, iTerm2). Everything it
displays already exists in the library's event stream after
[20260803-03-metadata-artwork.md](20260803-03-metadata-artwork.md), except
two fields this plan adds.

Requested content on screen (all confirmed):

- title / artist / album, centered
- cover art as an image where the terminal supports it
- idle vs connected state, and the receiver's own name
- volume
- audio format (rate, channels)
- elapsed / total time
- the sender's IP address

The last two are not available today — hence a library phase before the TUI
itself.

## What already exists, and what has to be added

The binary is the library's embedder #1 and consumes only its public API;
that stays true here. Today's `Event`s give the TUI most of what it needs:
`SessionStarted { rate, channels }`, `Volume { db }`, `Metadata`, `Artwork`,
`Flushed`, `SessionEnded`. Two gaps:

**Elapsed / total time.** Senders push
`SET_PARAMETER text/parameters` with `progress: <start>/<current>/<end>` —
three RTP timestamps — whenever position changes. We advertise `md=0,1,2`
(the third being progress), so senders already send it; we currently parse
only the `volume:` line out of that body and ignore the rest. This plan adds
the parse and a new event.

Timestamps are wire concepts, and the invariant is that they stay out of the
public API, so the library converts them with the session's sample rate and
emits **durations**:

```rust
/// SET_PARAMETER progress. Position within the current track.
Event::Progress {
    elapsed: Duration,   // (current - start) / rate
    duration: Duration,  // (end - start) / rate
},
```

Senders send this every few seconds, not per frame, so the TUI extrapolates
between updates from its own clock (clamped to `duration`) and re-syncs on
each event.

**The sender's IP.** `Session` knows the peer address (it addresses resend
requests with it) but never surfaces it. The natural home is
`SessionStarted`, which is exactly the "a sender connected" moment:

```rust
#[non_exhaustive]
SessionStarted {
    rate: u32,
    channels: u8,
    peer: IpAddr,   // new
},
```

**This is a breaking change** for anyone matching
`Event::SessionStarted { rate, channels }` — the crate is published, so it
means **0.2.0**, and radiod's match arm needs `..` added when it bumps. The
alternative — a separate `Event::SenderConnected { peer }` variant, which
would be non-breaking on the `#[non_exhaustive]` enum — was considered and
rejected: two events for one moment, with an ordering question between them,
to dodge a version bump on a 0.1 crate with two known embedders. Worth
mirroring in openairplay2 later for parity; out of scope here.

> **Changed during implementation:** this plan also said to mark the
> *variant* `#[non_exhaustive]` so later fields would be additive. Doing so
> makes the variant impossible to **construct** outside the library, and
> hosts do construct it — the TUI's own layout tests build a
> `SessionStarted` to render, and radiod's tests would too. The variant is
> therefore left constructible, and a future field addition stays breaking
> (acceptable on 0.x, and the separate-variant escape hatch above remains
> available). The enum-level `#[non_exhaustive]` is untouched, so *new
> variants* are still additive.

## The TUI

**Layout.** One centered column: artwork block on top, then title (bold),
artist, album, then a dim status line. Idle state replaces the track block
with the receiver name and "waiting for a sender…". Nothing scrolls,
nothing is interactive except `q`/`Ctrl-C` to quit.

```
┌────────────────────────── 96x30 ───────────────────────────┐
│                                                            │
│                    ┌──────────────┐                        │
│                    │              │                        │
│                    │   artwork    │                        │
│                    │              │                        │
│                    └──────────────┘                        │
│                                                            │
│                      Sonata No. 1                          │
│                       Some Artist                          │
│                       Some Album                           │
│                                                            │
│                 ━━━━━━━━━━━━━━━━━━━━━━━                     │
│                    1:23 / 4:07                             │
│                                                            │
│    Living Room · 192.168.1.42 · 44100 Hz 2ch · -12.5 dB    │
└────────────────────────────────────────────────────────────┘
```

**Stack: ratatui + crossterm** (Stefan's call over a hand-rolled centering
pass) — layout constraints, and room to grow into panes or meters later. In
the binary only; the library gains no TUI dependency and stays macOS-green.

**Logging has to go somewhere else.** `env_logger` writing to stderr would
shred the screen. With `--tui`, log output is suppressed unless
`--log-file PATH` is given, in which case the logger writes there instead.
`--log-file` works without `--tui` too (it is just a sink change).

**Terminal restore is not optional.** Alternate screen + hidden cursor + raw
mode, restored on `q`, on `Ctrl-C`, on a fatal error, **and from a panic
hook** — a receiver that leaves the terminal in raw mode with no cursor on a
panic is worse than no TUI. Resize events trigger a redraw and re-place the
artwork.

## Artwork: Kitty graphics and iTerm2 inline images

Two protocols cover the terminals that matter (Stefan's call):

| Terminal | Protocol |
|---|---|
| Ghostty, Kitty | Kitty graphics (`APC _G … ST`) |
| WezTerm | either (prefer Kitty) |
| iTerm2, Konsole | iTerm2 inline images (`OSC 1337 File=inline`) |
| anything else | text only, no image |

**Format handling.** iTerm2's protocol takes the file bytes as-is, so JPEG
and PNG both pass straight through as base64 — nothing to decode. Kitty
accepts PNG (`f=100`) or raw pixels (`f=24`/`f=32`), and senders overwhelmingly
send JPEG, so the JPEG path decodes to RGB with `jpeg-decoder` (small and
focused; the `image` crate would pull far more for one format). PNG goes
through as `f=100` untouched.

**Sizing.** Both protocols can place an image into a cell box and let the
terminal scale (`c=`/`r=` for Kitty, `width=`/`height=` in cells for iTerm2),
so we never resample. To keep the aspect ratio right we need the cell pixel
size: `TIOCGWINSZ`'s `ws_xpixel`/`ws_ypixel` when the terminal fills it in,
falling back to assuming a 1:2 cell. The artwork box is capped at a fraction
of the screen so the text always fits.

**Detection.** Probe, then fall back to environment. The Kitty probe is the
protocol's own query (`a=q` with a 1×1 image) with a short read timeout; if
it answers `OK`, Kitty graphics work. Otherwise `TERM`/`TERM_PROGRAM`/
`KITTY_WINDOW_ID`/`GHOSTTY_*`/`KONSOLE_VERSION` decide, and anything
unrecognized gets text only. `--tui-images=auto|kitty|iterm2|none` forces the
choice for testing and for terminals that lie.

**Lifecycle.** Kitty images persist until deleted, so the TUI owns one image
id: delete-then-draw on track change, delete on `Artwork` with empty data
(the `image/none` clear), delete on exit. Only the latest artwork bytes are
kept in memory.

## Testing

The library phase is ordinary unit-test work: `progress:` parsing (including
malformed and out-of-order values, and `start == end`), the timestamp →
`Duration` conversion at the session sample rate, and `peer` reaching
`SessionStarted` (the existing session tests already assert on that event).

For the TUI, the parts worth testing are the ones that are pure:

- **Layout**, via ratatui's `TestBackend`: render a frame into a buffer and
  assert the centering and the content — idle vs playing, missing fields
  (title-only metadata), a very narrow terminal, and a terminal too short for
  artwork.
- **Escape-sequence builders**: assert the exact bytes for a small known
  image, both protocols, including the delete sequence. These are pure
  functions over `(bytes, placement)` and are where a typo would otherwise
  cost a hardware round trip.
- **Capability detection**, as a pure function over an env map plus an
  optional probe result, so every terminal in the table above is a test case.
- **Elapsed extrapolation**: given a `Progress` event and elapsed wall time,
  the displayed position advances and clamps at `duration`.

What can't be unit-tested is the real thing, so acceptance includes a manual
run in Ghostty (artwork appears, changes with the track, clears on
`image/none`, survives a resize, terminal restored on `Ctrl-C` and on a
forced panic) and a check in a plain `xterm` that the text-only fallback is
clean.

## Scope

In scope: `Event::Progress`; `peer` on `SessionStarted` (+ 0.2.0 bump);
`--tui`, `--log-file`, `--tui-images`; the ratatui screen with all seven
requested content items; Kitty and iTerm2 artwork with detection, sizing and
lifecycle; the tests above.

Out of scope: Sixel (few of the terminals in use need it, and it means color
quantization); mouse or keyboard interaction beyond quit; a log pane; any
artwork handling inside the library (it still ends at PCM + events);
mirroring the `SessionStarted` change into openairplay2; DACP transport
control.

## Phases

1. **Library: progress and peer** — parse `progress:` in the
   `text/parameters` path, add `Event::Progress` (durations, not RTP
   timestamps), add `peer` to `SessionStarted` and mark that variant
   `#[non_exhaustive]`, bump to 0.2.0, update the receiver's existing match
   arms. Unit tests.
2. **`--tui` screen** — ratatui + crossterm, the centered layout with idle
   and playing states, all non-artwork content, `--log-file` and the logging
   redirect, terminal setup/restore including the panic hook, resize
   handling. `TestBackend` layout tests.
3. **Artwork** — capability detection with the Kitty probe and env fallback,
   `--tui-images`, the two protocol encoders (JPEG decode for Kitty, direct
   passthrough for iTerm2), cell-size/aspect handling, image lifecycle
   (replace, clear, exit). Encoder and detection tests.

## Acceptance criteria

- `--tui` shows title/artist/album centered, plus receiver name, sender IP,
  format, volume, and elapsed/total, updating live across track changes; idle
  state before and after a session.
- Artwork renders as an image in Ghostty, updates on track change, disappears
  on the sender's `image/none` clear, and re-places correctly after a resize;
  a terminal without support shows the text-only layout with no stray escape
  bytes.
- The terminal is left clean on `q`, `Ctrl-C`, error exit, and panic.
- Without `--tui` the binary behaves exactly as today (logs to stderr, no
  terminal manipulation).
- Library still ALSA-free and macOS-green; workspace clippy/fmt/rustdoc clean;
  no new library dependencies (the TUI ones live in the binary).
- Hardware validation with a real sender in Ghostty, per the plan above.

## Status

Approved; all three phases implemented (PRs #27, #28, #29). Workspace tests,
clippy `-D warnings`, fmt and rustdoc clean throughout.

Two things worth recording from the build:

- The `#[non_exhaustive]` variant idea did not survive contact — see the note
  above. It surfaced immediately, because the TUI's own tests construct
  `SessionStarted`.
- The screen and the artwork path were verified end to end in a real pty
  (`script` with a set size), driven by a synthetic RAOP sender: title,
  artist, album, sender address, format, volume and a `0:10 / 3:00` clock all
  render; the Kitty escape carries the decoded image into its cell box and is
  deleted on exit; `--tui-images none` emits no graphics bytes at all. Both
  terminal-restore paths (`q` and SIGTERM) leave the alternate screen and
  restore the cursor.

Outstanding: hardware validation in Ghostty with a real sender — artwork
appearing and changing per track, the `image/none` clear, a resize, and the
text-only fallback in a plain `xterm`.
