# Publish openairplay1 to crates.io

Goal: make `openairplay1` installable as a normal crates.io dependency
(`openairplay1 = "0.1"`) instead of a git reference, with docs on
docs.rs, and make releasing repeatable. Research findings first, then
the work; the code changes themselves are small — most of this is
metadata, documentation, and automation. Adapted from the sister
project's plan (`openairplay2/plans/20260802-02-crates-io.md`,
implemented there in PRs #25–#29).

## Research findings (2026-08-03)

**Ready already:**

- The crate names `openairplay1` and `openairplay1-receiver` are
  **unclaimed** on crates.io (checked via the crates.io API today).
- Licensing housekeeping is done: `LICENSE` (MIT) and `NOTICE.md`
  (shairport-sync attribution + AirPort-key caveat) exist at the repo
  root, and `license = "MIT"` is declared.
- `cargo package -p openairplay1` succeeds; the package is small
  (source, the 4 KB `airport.pem`, and ~20 KB of golden ALAC test
  fixtures). All dependencies are crates.io releases (no git/path deps
  in the library) and pure Rust — no system libraries — so **docs.rs
  will build it without special metadata**, and so will any consumer on
  any platform.
- Most discovery/linkage metadata already landed with the
  embeddable-library refactor: `repository`, `keywords`, `categories`,
  `rust-version` (1.87, the floor set by `u64::is_multiple_of`) are
  set on both crates.
- The documentation pass is largely done: `#![warn(missing_docs)]` is
  in `lib.rs` and the build is warning-free; the crate-level rustdoc
  carries a compile-checked embedding example (it runs as a doctest).

**Gaps:**

- `Cargo.toml` lacks `readme` (and `documentation`) — the crates.io
  page would render without the README.
- `LICENSE` and `NOTICE.md` live at the workspace root, so they are
  **not included in the published package** (the package only picks up
  the crate directory). `NOTICE.md` matters: `airport.pem` ships in
  the crate, and its attribution/caveat should travel with it.
- **No CI at all** (`.github/workflows/` doesn't exist). The "library
  must stay macOS-green" deliverable is enforced only by discipline,
  and there is no release automation.
- `openairplay1-receiver`'s path dependency has no `version`, so the
  binary crate as-is cannot be published (fine unless we choose to).

**Decisions for Stefan (the plan assumes the recommended defaults):**

1. **Publishing the AirPort key.** `airport.pem` — the well-known
   AirPort Express RSA private key, Apple-derived, taken verbatim from
   shairport-sync — would now be redistributed via crates.io, not just
   GitHub. This is the same gray area notes/licensing.md documents —
   NOTICE.md attributes and explains it, every hobby AirPlay 1
   receiver ships it, and crates.io policy doesn't forbid it, but it
   is Stefan's call to accept. *Recommendation: publish as-is with
   NOTICE.md included in the package.*
2. **Publish the receiver binary crate too?** Publishing
   `openairplay1-receiver` enables `cargo install openairplay1-receiver`
   on Linux. *Recommendation: yes, but as the last phase — it is cheap
   once the library is up (add `version` to the path dep).*
3. **Radio's dependency** can later switch from the git reference to
   the published version — out of scope here, radio-side change.

## Scope

In scope: crate metadata, packaging the license/notice files, a
re-read of the docs, CI (test/clippy/fmt on Linux **and** macOS — the
portability deliverable, finally enforced), release automation via
crates.io **Trusted Publishing** (GitHub OIDC — no long-lived API
token secret), a short releasing runbook, and the `v0.1.0` release
itself.

Out of scope: any behavior change; README rewrites beyond what
publishing needs (badges + install line); radio's switch to the
published crate; docs.rs feature flags (the crate has no features).

## Phases

1. **Packaging metadata.** `openairplay1/Cargo.toml`: add
   `readme = "../README.md"` and
   `documentation = "https://docs.rs/openairplay1"`. Ship `LICENSE` +
   `NOTICE.md` inside the package (symlink into the crate dir, as
   openairplay2 does — cargo dereferences them; verify with
   `cargo package --list`). Same `readme` for the receiver crate.
   Acceptance: `cargo publish --dry-run -p openairplay1` clean, no
   manifest warnings, license/notice visible in `--list`.

2. **Documentation re-read.** The missing-docs work is done; re-read
   the crate-level docs and the README embedding example as a
   first-time embedder would, fix anything stale after the refactor.
   Acceptance: zero missing-docs warnings; `cargo doc --no-deps`
   clean.

3. **CI + release automation.** `ci.yml`: build, test, clippy, fmt on
   `ubuntu-latest` (with `libasound2-dev`, whole workspace) and
   `macos-latest` (`cargo test -p openairplay1` + clippy — the
   portable subset), on PRs and main. `release.yml`: on pushing a `v*`
   tag, run tests then `cargo publish -p openairplay1` followed by
   `-p openairplay1-receiver` using crates.io Trusted Publishing
   (configure the GitHub repo/workflow as the trusted publisher on
   crates.io — the first publish needs a manual `cargo publish` with a
   token to create the crates before trust can be configured; the
   runbook covers this). Add `runbooks/releasing.md`: bump version,
   tag, verify docs.rs. CLAUDE.md grows the runbook/CI note.
   Acceptance: CI green on both OSes; a dry-run of the release path.

4. **Release `v0.1.0`, then the receiver (per decision 2).** Publish
   the library (Stefan triggers — tag push or first manual publish),
   verify the crates.io page and docs.rs render, README gets the
   crates.io/docs.rs badges, an "add it to Cargo.toml" line, and a
   `cargo install openairplay1-receiver` line. Then
   `openairplay1-receiver`: add `version = "0.1"` to the path
   dependency, publish.

## Test strategy

Phases 1–2 are verified by cargo itself (`publish --dry-run`,
`package --list`, doc builds) — no behavior changes, the full existing
suite must stay green. Phase 3 is verified by the workflows running on
the PRs that introduce them (CI proves CI). Phase 4 by the live
crates.io page, `docs.rs/openairplay1` rendering, and a scratch
project depending on `openairplay1 = "0.1"` building the lib.rs
example.

## Acceptance criteria

- `cargo publish --dry-run -p openairplay1` passes with no warnings;
  the packaged crate contains `LICENSE` and `NOTICE.md`.
- Zero `missing_docs` warnings; docs.rs builds and renders.
- CI runs test/clippy/fmt on Linux and macOS for every PR; releasing
  is a tag push (after one-time trusted-publisher setup), documented
  in a runbook.
- `openairplay1 = "0.1"` from crates.io compiles the README embedding
  example; the `AudioSink`/event contracts are unchanged.
